# 升级与维护指南（数据管理定制版）

> 面向：持续跟随官方 `router-for-me/CLIProxyAPI` 更新，同时保住本地「数据管理」功能。
> 仓库：`E:\guahub\gh\CLIProxyAPI`，fork 于 `github.com/ggbdpq/CLIProxyAPI`。

## 一、仓库拓扑（双 remote + custom 分支）

```
origin    = https://github.com/ggbdpq/CLIProxyAPI.git      # 个人 fork，push 目标
upstream  = https://github.com/router-for-me/CLIProxyAPI   # 官方，只读

main      # 跟随官方（只同步，不直接开发）
custom    # 承载全部本地差异，日常构建/部署用这个分支
```

**核心心智**：`custom` 分支是唯一需要维护的差异面。升级 = 把 custom 上的提交重放到官方最新之上（rebase），冲突只可能出现在极小的补丁面（见下）。

## 二、本地差异总览

对官方的侵入被压缩到 **2 个被修改的官方文件 + 2 个新增文件**：

### A. 修改官方文件（rebase 时需检查，冲突概率低）

| 文件 | 改动内容 | 冲突风险 |
|---|---|---|
| `internal/api/handlers/management/api_tools.go` | 数据记录 9 条 API 的路由处理 + `/api-call` 代理 + Codex 配额回写 | 低——追加式修改，与官方逻辑不重叠 |
| `internal/api/server_management.go` | 9 条 `/data-records*` 路由注册 + `dataRecordsStore()` + `registerDataMgmtSPA()` 挂载 | 低——追加式修改 |

> `updater.go`/`updater_test.go` 已回官方版，**不再是补丁面**。

### B. 新增文件（官方无，rebase 自动保留）

| 文件 | 说明 |
|---|---|
| `custom-addon/backend/data_records.go` + 测试 | 后端核心（package `datarecords`，内嵌 node:sqlite 脚本），module 内 import 编译进二进制 |
| `custom-addon/frontend/` | React SPA（React 19 + TanStack Router/Query/Table + Zustand + Zod + Tailwind 4），`pnpm build` 产出 `dist/`（不入库） |
| `internal/api/data_mgmt_spa.go` | `/data-mgmt/` 静态 serve + SPA fallback；dist 定位：环境变量 `CPA_DATA_MGMT_DIST` 覆盖 → 配置目录/cwd/exe 目录向上逐级查找 `custom-addon/frontend/dist` |
| `internal/api/handlers/management/api_tools_quota_test.go` | 配额回写测试（独立文件，避免与官方测试冲突） |

**归档**：A 类文件在 `custom-addon/modified-files/` 存快照（独立 module，不参与编译），`verify-archive.ps1` 校验一致性。**源码树是编译权威；`backend/`、`frontend/` 是单一来源，归档不存副本。**

## 三、升级流程（每次官方更新）

```powershell
cd E:\guahub\gh\CLIProxyAPI

# 0. 确认工作区干净（rebase 前提）
git status

# 1. 备份数据（data-records.sqlite + config.yaml）
powershell -ExecutionPolicy Bypass -File custom-addon\scripts\backup-data.ps1

# 2. 拉官方最新并重放差异
git fetch upstream
git checkout custom
git rebase upstream/main

# 3. 处理冲突（若有）：只可能在 api_tools.go / server_management.go
#    解决后 git add <文件> && git rebase --continue

# 4. 回归验证
go build ./...     # GOPROXY 被墙时加前缀 GOPROXY=https://goproxy.cn,direct
go test ./internal/... ./custom-addon/backend/...

# 5. 重新编译（前端 + 后端）
powershell -ExecutionPolicy Bypass -File custom-addon\scripts\build.ps1

# 6. 校验归档同步
powershell -ExecutionPolicy Bypass -File custom-addon\scripts\verify-archive.ps1

# 7. 推送（rebase 改写历史，需强推 fork）
git push --force-with-lease origin custom
```

> 不想改写历史可改用 `git merge upstream/main`，冲突处理相同，但提交图会保留官方节点。

## 四、前端开发与构建

```powershell
cd custom-addon\frontend

pnpm install        # 首次 / 依赖变更后
pnpm dev            # 开发模式：http://localhost:5173/data-mgmt/，/v0 自动代理到 127.0.0.1:8317
pnpm typecheck      # tsc -b
pnpm build          # 产出 dist/（Go 运行时 serve 这个目录）
```

- 开发时先起后端（`go run ./cmd/server --config config.yaml`），再 `pnpm dev`，浏览器访问 5173。
- 技术栈要点：TanStack Table 是 **v9**（`useTable` + `tableFeatures` + `table.FlexRender`，网上多数教程还是 v8 的 `useReactTable`，勿照抄）；TypeScript 7 无 `baseUrl`（paths 用相对路径）。用法参考可翻 `node_modules/@tanstack/react-table/skills/`。

## 五、注意事项清单

1. **数据不参与升级**：`data/`（含 `data-records.sqlite`）与 `config.yaml` 不提交，升级前用 `backup-data.ps1` 备份。
2. **本地排除**：`data/`、`backup/` 等在 `.git/info/exclude`（本地排除，不污染上游 diff）；换机需手动迁移。
3. **LF/CRLF**：`core.autocrlf=true`，git 内部存 LF，工作区 CRLF 警告属正常。
4. **GOPROXY**：proxy.golang.org 被墙，临时用 `GOPROXY=https://goproxy.cn,direct go build ...`；永久生效 `go env -w GOPROXY=https://goproxy.cn,direct`。
5. **fnm 坑**：在 E 盘 `cd` 触发 use-on-cd hook 报错且断 `&&` 链，Git Bash 里用 `;` 代替 `&&`。
6. **双份拷贝**：`modified-files/` 与源码树需保持一致，改 A 类文件后跑 `verify-archive.ps1`，漂移则拷贝源码树版本进归档。
7. **exe 是产物**：`custom-addon/exe/` 不入库，换机重新 `build.ps1`。
8. **归档目录的 go.mod**：`modified-files/go.mod` 是刻意的独立 module（防 `go build ./...` 误编译归档副本），勿删。
9. **管理密钥**：SPA 登录密钥存 localStorage（键 `cpa-data-management-key`），对应 `config.yaml` 的 `secret-key`。
10. **测试环境**：数据管理测试需带内建 `node:sqlite` 的 Node（v22.5+/v24+），缺失时自动 skip。

## 六、脚本清单（`custom-addon/scripts/`）

| 脚本 | 用途 |
|---|---|
| `build.ps1` | 前端 `pnpm build` + Go 编译串联，产出 `custom-addon/exe/cli-proxy-api-datamgmt.exe`；`-SkipFrontend` 跳过前端（只改后端时） |
| `backup-data.ps1` | 备份 `data/data-records.sqlite` 与 `config.yaml` 到项目根 `backup/`（带时间戳） |
| `verify-archive.ps1` | 校验 `modified-files/` 与源码树一致 + 单一来源文件存在；exit 0/1 可用于 CI |

> 旧的 `start-8317.bat`（CPA_PLUGIN_UI 插件注入形态启动器）已随注入形态退役删除。

## 七、一句话总结

**升级心智一条线**：`git fetch upstream && git rebase upstream/main`，冲突只可能在 2 个文件，重放后 `build.ps1` + `verify-archive.ps1` 收尾。custom 分支之外的世界与官方完全同步。
