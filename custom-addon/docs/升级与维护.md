# 升级与维护指南（数据管理补丁）

> 面向：持续跟随官方 `router-for-me/CLIProxyAPI` 更新，同时保住本地「数据管理」补丁。
> 归档目录：`custom-addon/`（本仓库的个人自定义模块；`backend/`、`frontend/` 是单一来源，直接参与编译/运行时加载）。

补丁分两类，升级时处理方式完全不同：

### A. 修改官方文件（升级会被覆盖，需重放）

| 文件 | 改动内容 | 升级冲突风险 |

| `internal/api/handlers/management/api_tools.go` | Codex 配额回写：`syncCodexQuotaNextTimeFromAPICall` + 配套函数 + `dataRecordsStore()` | 低——官方近期只加 `proxy_url` 参数支持，位置不重叠 |

> `config.example.yaml` 已不打补丁，保持官方原样；本地差异（端口 8318、`auth-dir` 等）只在 `config.yaml`（不入库）。

### B. 新增文件（官方无，升级后直接保留）

| 文件 | 说明 |

| `custom-addon/backend/data_records.go` + `data_records_test.go` | 数据管理后端（package `datarecords`，内嵌 node:sqlite 脚本），module 内 import 编译进二进制，**天然解耦** |

## 二、官方同步策略（推荐：补丁分支）

### 为什么当前状态最脆弱

- `main` = 官方 v7.2.145（HEAD=d9cea890），但 A 类补丁**未提交、散在工作区**（`git status` 的 4 个 modified 文件）。
- 直接 `git pull` 会因工作区脏而失败；无法 `git stash` 干净隔离；无法回滚到「补丁之前」；换机/误操作即丢失。
- 另注意：`custom-addon/` 与 `data/` 通过 `.git/info/exclude`（本地排除）对 git 隐身，换机时这两个目录不会随仓库走，需单独备份。

### 第一步（一次性）：把补丁固化到 `custom` 分支

```powershell
cd C:\Users\802165\vibe\inbox\cpa-manage
# 1. 在当前官方基线上创建补丁分支
git checkout -b custom

# 2. 加入补丁文件（4 个修改 + 1 个新增测试）
git add internal/api/handlers/management/api_tools.go `
        internal/api/handlers/management/api_tools_quota_test.go `
        internal/api/server_management.go `
        internal/managementasset/updater.go `
        internal/managementasset/updater_test.go

# 3. 提交为补丁基线
git commit -m "feat(custom): 数据管理补丁基线（v7.2.145）"

# 4. 回到 main，保持官方追踪干净
git checkout main
```

> 之后 `main` 只用来追踪官方代码，`custom` 承载补丁。`custom-addon/`、`data/`、`config.yaml` 维持本地排除/忽略，不进 git。

### 第二步（每次官方更新）

```powershell
git fetch origin                    # 拉官方最新
git checkout custom
git rebase origin/main              # 把补丁 rebase 到官方最新之上
```

- **冲突只可能出现在**：`api_tools.go`、`server_management.go`、`updater.go`、`updater_test.go`。
- 实践上官方近期演进已证明：这些文件冲突概率极低，但**每次必须检查**。
- 处理完冲突后**校验归档**（见第四节），确保 `custom-addon/modified-files/` 与源码树一致。

### 备选：保守方案

不想 `rebase` 改写历史，可用 merge：

```powershell
git checkout custom
git merge origin/main
```

历史保留官方节点，冲突处理方式相同。

## 四、注意事项清单

1. **升级前先备份数据**：`data/`（含 `data-records.sqlite`）与 `config.yaml` 不提交、不参与升级，但要手动备份（`backup-data.ps1`）。
2. **`custom-addon/` 与 `data/` 在 `.git/info/exclude` 中**：换机或重克隆不会带上它们，需手动拷贝；不要把这两条移入公开的 `.gitignore` 提交。
3. **rebase 前确认工作区干净**：`git status` 无未提交改动，否则 rebase 会拒绝。
4. **LF/CRLF**：官方文件为 LF；本地 Git 会提示 CRLF 替换警告，正常现象，不影响编译。改补丁文件时注意不要整体改写换行。
5. **双份拷贝**：`custom-addon/modified-files/` 与源码树是两份拷贝。**以源码树为准**，升级后运行 `verify-archive.ps1` 保持一致；`backend/`、`frontend/` 是单一来源，归档不存副本。
6. **exe 是构建产物**：已被 `.gitignore` 忽略，换机器需重新编译（用 `build.ps1`）。
7. **编译版本号**：本地编译显示 `Version: dev, Commit: none`，不影响功能；需要时可用 `-ldflags` 注入版本。
8. **管理密钥**：`config.yaml` 里的 `secret-key` hash 不提交，升级不涉及。
9. **测试环境**：数据管理/配额回写的测试需要带内建 `node:sqlite` 的 Node（v22.5+/v24+），缺失时 `api_tools_quota_test.go` 的集成测试会自动 skip，其余测试照常。

## 五、脚本（已落地 `custom-addon/scripts/`）

四个脚本已实体化，均在 `custom-addon/scripts/`（UTF-8 BOM，中文正常显示）。脚本内部自动定位项目根，可从任意位置调用：

| 脚本 | 用途 | 调用方式 |
|---|---|---|
| `build.ps1` | 编译一份二进制并复制为两种 exe 到 `custom-addon/exe/`（先检查占用；8317 形态靠运行时 `CPA_PLUGIN_UI=1` 区分） | `powershell -ExecutionPolicy Bypass -File custom-addon\scripts\build.ps1` |
| `start-8317.bat` | 启动 8317 插件注入形态（自动设 `CPA_PLUGIN_UI=1`、定位 exe 与工作目录；GBK 编码） | `custom-addon\scripts\start-8317.bat` |
| `backup-data.ps1` | 备份 `data/data-records.sqlite` 与 `config.yaml` 到项目根 `backup/`（带时间戳） | `powershell -ExecutionPolicy Bypass -File custom-addon\scripts\backup-data.ps1` |
| `verify-archive.ps1` | 对比源码树补丁文件与 `custom-addon/modified-files/`，报告漂移；并检查 `backend/`、`frontend/` 单一来源文件存在 | `powershell -ExecutionPolicy Bypass -File custom-addon\scripts\verify-archive.ps1` |

**升级后的标准三步**：

```powershell
cd C:\Users\802165\vibe\inbox\cpa-manage
# 1. 备份数据（rebase 前必做）
powershell -ExecutionPolicy Bypass -File custom-addon\scripts\backup-data.ps1
# 2. 校验归档与源码树一致
powershell -ExecutionPolicy Bypass -File custom-addon\scripts\verify-archive.ps1
# 3. 重新编译 exe
powershell -ExecutionPolicy Bypass -File custom-addon\scripts\build.ps1
```

> 手动编译命令等价：`go build -o custom-addon\exe\cli-proxy-api-datamgmt.exe ./cmd/server && Copy-Item custom-addon\exe\cli-proxy-api-datamgmt.exe custom-addon\exe\cli-proxy-api-8317.exe`；8317 插件注入形态在启动时设 `CPA_PLUGIN_UI=1`（用 `start-8317.bat` 即可）。

## 六、一句话总结

**把补丁从「工作区散件」变成「custom 分支」**，官方升级走 `git fetch origin && git rebase origin/main`，冲突只会在 4 个文件，升级后跑 `verify-archive.ps1` 保证归档同步。这套流程让「跟随官方 + 保住补丁」从手动操作变成可重复的确定性流程。
