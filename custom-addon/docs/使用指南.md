# CLIProxyAPI 使用指南

本文档面向 Windows PowerShell 环境，说明如何在本地配置、启动和调用 CLIProxyAPI（数据管理定制版）。

## 1. 首次配置

当前仓库默认提供 `config.example.yaml` 模板。如果根目录没有 `config.yaml`，先复制一份：

```powershell
cd E:\guahub\gh\CLIProxyAPI
Copy-Item config.example.yaml config.yaml
```

然后编辑 `config.yaml`，至少确认以下配置：

```yaml
host: "127.0.0.1"
port: 8317

auth-dir: "~/.cli-proxy-api"

api-keys:
  - "你自己设置的访问密钥"

remote-management:
  secret-key: "你自己设置的管理密钥"
```

注意：不要保留 `your-api-key-*` 这类示例密钥，否则代理 API 会进入 safe mode。

## 2. 启动服务

### 2.1 开发方式运行

```powershell
go run ./cmd/server --config config.yaml
```

如果只是本地快速启动，并希望跳过远程模型目录更新：

```powershell
go run ./cmd/server --config config.yaml --local-model
```

### 2.2 编译后运行

```powershell
go build -o cli-proxy-api.exe ./cmd/server
.\cli-proxy-api.exe --config config.yaml
```

### 2.3 TUI 模式

```powershell
.\cli-proxy-api.exe --config config.yaml --tui --standalone
```

### 2.4 数据管理版编译产物（custom-addon/exe）启动

本仓库的「数据管理」版 exe 在 `custom-addon/exe/cli-proxy-api-datamgmt.exe`（唯一一份二进制，旧的 8317/8318 双形态已退役）。数据管理 UI 是独立 SPA，访问 `/data-mgmt/` 子路径，与官方面板（`/management.html`，纯官方原样）零耦合。

**正确启动方式**（不要直接双击 exe，双击会以 exe 所在目录为工作目录而找不到 `config.yaml`）：

```powershell
cd E:\guahub\gh\CLIProxyAPI
custom-addon\exe\cli-proxy-api-datamgmt.exe --config config.yaml
```

> 双击 exe 的失败表现：`failed to read config file: open ...\custom-addon\exe\config.yaml: The system cannot find the file specified.`

SPA 构建产物在 `custom-addon/frontend/dist/`，Go 运行时自动定位（config 目录 / cwd / exe 目录向上逐级查找）；也可用环境变量 `CPA_DATA_MGMT_DIST` 显式指定 dist 目录。

## 3. 登录或导入账号

常用 OAuth 登录命令：

```powershell
.\cli-proxy-api.exe --config config.yaml --codex-login
.\cli-proxy-api.exe --config config.yaml --codex-device-login
.\cli-proxy-api.exe --config config.yaml --claude-login
.\cli-proxy-api.exe --config config.yaml --antigravity-login
.\cli-proxy-api.exe --config config.yaml --kimi-login
.\cli-proxy-api.exe --config config.yaml --xai-login
```

导入 Vertex 服务账号：

```powershell
.\cli-proxy-api.exe --config config.yaml --vertex-import path\to\service-account.json
```

## 4. 启动后验证

健康检查：

```powershell
curl http://127.0.0.1:8317/healthz
```

列出模型：

```powershell
curl http://127.0.0.1:8317/v1/models `
  -H "Authorization: Bearer 你的访问密钥"
```

管理面板：

```text
http://127.0.0.1:8317/management.html     # 官方面板（纯官方原样）
http://127.0.0.1:8317/data-mgmt/          # 数据管理 SPA（密钥登录后使用）
```

## 5. 客户端接入方式

OpenAI 兼容客户端通常这样配置：

```text
Base URL: http://127.0.0.1:8317/v1
API Key: 你在 config.yaml 里配置的 api-keys
```

常用端点：

```http
GET  /v1/models
POST /v1/chat/completions
POST /v1/responses
POST /v1/messages                 # Claude/Anthropic 风格
GET  /v1beta/models               # Gemini 风格
POST /v1beta/models/*action
POST /backend-api/codex/responses # Codex 直连别名
```

支持的鉴权方式：

```http
Authorization: Bearer <api-key>
X-Api-Key: <api-key>
X-Goog-Api-Key: <api-key>
```

也可以通过查询参数传入：

```text
?key=<api-key>
```

## 6. 常见问题

### 6.1 PowerShell 提示找不到 `go`

错误示例：

```text
go : 无法将“go”项识别为 cmdlet、函数、脚本文件或可运行程序的名称。
```

说明本机没有安装 Go，或 Go 没有加入 `PATH`。可先安装 Go，然后重开 PowerShell：

```powershell
winget install --id GoLang.Go -e
go version
```

如果已安装但当前窗口识别不到，可临时补充 PATH：

```powershell
$env:Path += ";C:\Program Files\Go\bin"
go version
```

### 6.2 API 返回 safe mode 相关错误

通常是 `config.yaml` 里仍保留了示例密钥。把 `api-keys` 改成自己生成的随机密钥后重启服务。

### 6.3 启动日志提示「网络连接失败 / failed to fetch latest management release」

**原因**：启动时后台连 GitHub 拉取「管理面板最新 release 信息」，被 GitHub API 限流，日志类似：

```text
[updater.go:278] failed to fetch latest management release information
error=... 403: API rate limit exceeded for <IP> ...
```

**这是外部网络/GitHub 侧问题，`warn` 级降级，不影响服务运行**——服务仍会正常监听端口（日志同时会看到 `API server started successfully on: :<port>`）。

**处理**：无需处理；等待限流恢复或更换网络 IP 即可。与 exe 是否重新编译无关。

### 6.4 exe 是否需要重新编译

**一般不需要**。判断依据（三者都满足即无需重编）：

1. exe 编译时间不落后于源码（`internal/` 下最新源码修改时间应早于 exe 生成时间）；
2. 运行 `exe --help` 能正常输出参数说明；
3. 带 `--config` 启动，服务正常监听端口。

只有**改动了 Go 源码**之后才需要重新编译；**改动了前端源码**（`custom-addon/frontend/src/`）则需要重新 `pnpm build`（`build.ps1` 已串联）。

### 6.5 如何打包/编译 exe

**方式一（推荐）：一键脚本** `custom-addon/scripts/build.ps1`

```powershell
cd E:\guahub\gh\CLIProxyAPI
powershell -ExecutionPolicy Bypass -File custom-addon\scripts\build.ps1
```

脚本自动定位项目根，先构建前端（`custom-addon\frontend` 内 `pnpm build` 产出 `dist/`），再编译二进制到 `custom-addon\exe\cli-proxy-api-datamgmt.exe`。编译前会检查目标 exe 是否正被运行中的进程占用。只改了后端想跳过前端构建时加 `-SkipFrontend`。

**方式二（手动命令）**：

```powershell
cd E:\guahub\gh\CLIProxyAPI
Push-Location custom-addon\frontend; pnpm build; Pop-Location
go build -o custom-addon\exe\cli-proxy-api-datamgmt.exe ./cmd/server
```

**编译前注意**：

- 先停止正在运行的服务，否则 exe 被占用，`go build` 会报 `Access is denied`。
- exe 需在 `config.yaml`（项目根）所在目录带 `--config` 启动，见第 2.4 节；不要双击 exe。
- 编译会显示 `Version: dev, Commit: none`，属正常现象，不影响功能；如需版本号可加 `-ldflags`。
- `go build` 拉 GOPROXY 被墙时，临时加前缀 `GOPROXY=https://goproxy.cn,direct`，或 `go env -w` 永久设置。
- 运行时需要带内建 `node:sqlite` 的 Node（v22.5+/v24+）；机器上没有时，数据管理 API 会报错，其余功能不受影响。

## 7. 一句话版

复制 `config.example.yaml` 为 `config.yaml`，改掉 `api-keys` 和管理密钥，运行 `go run ./cmd/server --config config.yaml`，然后把客户端 `Base URL` 指向 `http://127.0.0.1:8317/v1`。

## 每次更新后，如果没刷新可以执行

停止正在运行的服务进程，然后重新编译并启动：

```powershell
powershell -ExecutionPolicy Bypass -File custom-addon\scripts\build.ps1
custom-addon\exe\cli-proxy-api-datamgmt.exe --config config.yaml
```
