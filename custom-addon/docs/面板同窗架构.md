# 面板同窗架构：反向嵌入设计

> 触发背景：2026-09 注入形态退役后，数据管理（`/data-mgmt/`）与官方面板（`/management.html`）分居两个站点，用户在「生成配额 → 配额管理 → 刷新配额 → 回写统计」的工作流中反复切换窗口，体验割裂。
> 目标读者：接手本模块的开发者。
> 覆盖范围：前端形态的架构决策、代码落点、闭环工作流、已知边界。后端 API 与升级流程见 `升级与维护.md`，不在此重复。

## 核心结论

数据管理 SPA 新增共享导航条与 `/panel` 路由，以**同源 iframe** 内嵌官方面板。三页同窗：

| 导航页 | 路由 | 内容来源 |
|---|---|---|
| 数据记录 | `/data-mgmt/` | 自研 SPA（SQLite 数据台账） |
| 批次台账 | `/data-mgmt/batches` | 自研 SPA（批次聚合账本） |
| 系统面板 | `/data-mgmt/panel` | 官方面板 `/management.html#/system`（iframe） |

设计本质是一次**依赖方向反转**：

- 旧形态：我们改官方 DOM（把扩展 HTML 拼进官方面板），官方每次改版都可能碰坏拼接点
- 新形态：官方页面作为整体被我们引用，只依赖其 URL，官方随便升级

## 形态演进

| 形态 | 时段 | 前端承载方式 | 对官方源码的侵入 | 结局 |
|---|---|---|---|---|
| 注入拼接 | 旧版（tag `legacy-inject-final` 前） | Go 把扩展 HTML 拼接到 `management.html` 的 `</body>` 前 | 改 `updater.go`/`server_management.go` 共 100+ 行 | 2026-09 退役，回官方版 |
| Chrome 扩展注入 | 旧版（8317 形态） | MV3 content script 注入官方页面 | Go 侧保留双形态开关 | 同批退役 |
| 独立 SPA + 反向嵌入 | 现行 | React SPA 子路径部署，iframe 引用官方面板 | 官方文件零改动 | 现行 |

## 代码事实地图

| 职责 | 文件 | 关键点 |
|---|---|---|
| 导航条 | `custom-addon/frontend/src/routes/__root.tsx` | 根路由渲染 `NAV_TABS` 三页 Tab，当前页高亮；未登录仍弹回 `/login` |
| 系统面板页 | `custom-addon/frontend/src/routes/panel.tsx` | `<iframe src="/management.html#/system">`，高度 `calc(100dvh - 3rem)`（导航条 h-12） |
| 子路径部署 | `custom-addon/frontend/src/main.tsx` + `vite.config.ts` | `basepath: '/data-mgmt'` 与 `base: '/data-mgmt/'` 必须同时声明（资源前缀与路由匹配是两套配置，缺一路由即渲染 Not Found） |
| 静态 serve | `internal/api/data_mgmt_spa.go` | Go 运行时读磁盘 `dist/`；SPA fallback 兜底 `/data-mgmt/*` |
| 配额反哺 | `internal/api/handlers/management/api_tools.go` | 官方面板刷新配额触发 `/wham/usage` 请求时，后端自动把 quota/status 回写 `data-records.sqlite`——**反哺在 Go 层，与前端形态无关** |
| dev 代理 | `custom-addon/frontend/vite.config.ts` | `/v0` 与 `/management.html` 均代理到 `127.0.0.1:8317`，`pnpm dev` 下 iframe 同样可用 |

闭环数据流（全链路不换窗口）：

```
数据记录页：导入 JSONL → 勾选 → 生成配额
    → 写 .cli-proxy-api/<email>.json 凭证文件
系统面板页（iframe）：配额管理可见新凭证 → 刷新配额
    → 官方请求 /wham/usage → api_tools.go 回写 SQLite
数据记录页：刷新 → quota/status 列已更新
```

## 设计取舍

被否方案对照：

| 方案 | 否决原因 |
|---|---|
| 回到 HTML 拼接注入 | 重写官方响应体，官方改版即碎；且刚为此收敛了补丁面（4 文件 → 2 文件），回退与「跟住上游」目标冲突 |
| 把官方面板功能在 SPA 里重写 | 配额管理/凭证管理体量大且持续演进，重写等于 fork 官方前端，维护成本失控 |
| 新标签页跳转官方面板 | 实现最简，但仍是两个窗口，未解决「同窗操作」诉求 |
| iframe 反向嵌入（采纳） | 同源零障碍、官方零侵入、升级零成本；代价见下节 |

## 已知边界与风险

| 边界 | 现状与判断 |
|---|---|
| 登录态两份 | SPA 存 `cpa-data-management-key`，官方面板存自己的键（内部实现混淆）。未做自动同步——官方键名随版本可变，同步逻辑会碎；两个密钥本是同一个明文，首次各输一次即可接受 |
| iframe 内 URL 不进浏览器历史 | 官方面板是 hash 路由，切换不污染外层地址栏；外层刷新回到 `#/system` 初始页，属可接受损耗 |
| CSP / X-Frame-Options | 官方当前未设置 frame 限制，同源嵌入可行；若未来官方加限制需改回新标签方案（`panel.tsx` 单文件可换） |
| 移动端体验 | iframe 高度占满视口，官方面板自身未针对小屏优化；本模块定位桌面工作台，暂不处理 |
| dev 模式 | `/management.html` 已加 vite 代理，`pnpm dev` 下 iframe 正常；若后端未启动则 iframe 404，属预期 |

## 可选演进（暂不做）

| 项 | 判断 |
|---|---|
| 登录态打通 | 依赖官方内部 localStorage 键名，碎风险高，收益低（多输一次）；官方若开放 URL 传参再跟进 |
| 官方面板多入口导航 | 现固定 `#/system`；如需直达其他页（如 API Key 管理），把 `panel.tsx` 的 hash 做成路由参数即可，单文件改动 |
| iframe 懒加载 | 当前 0.3KB chunk 按需加载已足够轻，无需进一步优化 |
