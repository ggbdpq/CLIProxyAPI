## 三、Phase 1-④:部署 / 回收 ⬜

**目标**:把「生成配额」升级为完整的「账号部署」闭环——从库存选号 → 生成凭证文件落到指定 auth 目录 → 记录部署状态;反向把失效账号从 auth 目录回收回库存。

### 3.1 后端(数据管理 API 新增两个动作)

- [ ] `POST /v0/management/data-records/deploy`
  - 入参:`{ ids: [], target: "local" | "official" | <白名单 key> }`
  - 行为:按选中记录生成 Codex 凭证 JSON(`<email>.json`,复用现有 `generate_quota_files` 的字段映射)写入目标目录;同邮箱已存在则覆盖
  - 回写:每条记录 `lifecycle = in_use`、`deployed_at = <now>`、`deploy_target = <target>`
  - 响应:`{ deployed, target, dir, files[] }`
- [ ] `POST /v0/management/data-records/recycle`
  - 入参:`{ ids: [], target: ... }`(或按 email)
  - 行为:删除目标目录中对应的 `<email>.json`;回写 `lifecycle = unused`、清空 `deployed_at`
  - 响应:`{ recycled, files[] }`
- [ ] 目标目录白名单(硬编码于后端,拒绝任意路径,防路径穿越):
  - `local`:本仓库 `.cli-proxy-api/`
  - `official`:`C:\Users\802165\CLIProxyAPI\.cli-proxy-api\`(8317 日常代理)
  - 白名单后续可在 config 或常量中扩充
- [ ] 保留现有 `generate-quota` 端点向后兼容(内部改为调 deploy 的 local 形态)

### 3.2 前端(库存页)

- [ ] 「生成配额」按钮升级为「部署」:按钮旁加目标目录下拉(本仓库 / 8317 官方目录)
- [ ] 选中 → 部署 → 结果弹窗(复用配额结果弹窗,显示目标目录与文件清单)
- [ ] 勾选已部署记录 → 「回收」按钮(需确认弹窗)
- [ ] 列表新增列:`deployed_at`(有值显示日期,点击表头可排序可后议)

### 3.3 验收标准

- [ ] 部署后目标目录出现 `<email>.json`,记录 `lifecycle=in_use`、有部署时间
- [ ] 回收后文件消失,记录回到 `unused`
- [ ] 非白名单路径一律 400;重复部署幂等(覆盖)

## 四、Phase 1-⑤:格式转换工具页 + 重授权登记 ⏸

### 4.1 格式转换工具页(面板新入口「工具」)

**范围(已裁剪)**:仅三种转换,其余格式(Cockpit/9router/AxonHub 等)等真实需求再加。

- [ ] `txt → CPA`:原版卡密 txt(逐行账号凭证)解析为 CPA 可用 JSON
- [ ] `CPA → sub2api`:从库存导出选中记录为 sub2api 格式 JSON
- [ ] `sub2api → CPA`:外部 sub2api JSON 导入转 CPA 格式
- [ ] 实现形态:**后端转换动作**(POST /v0/management/data-records/convert,`{ from, to, content }` 返回转换结果 + 可下载),前端独立工具页(输入框/文件上传 + 输出框 + 下载按钮),遵循「与库存数据隔离」原则:转换页不读不改库存,只处理用户显式粘贴/上传的内容
- [ ] 转换为纯函数,配单测(样本输入 → 期望输出)

**⏸ 卡点:需要你提供两个样本**(各 3~5 行即可,敏感字段可打码但保留字段结构):
1. 原版卡密 txt 样本(如 `01.GPT Free/2026-05/01.../01-ChatGPT原版卡密/卡密导出_20260620.txt`)
2. sub2api 格式 JSON 样本

### 4.2 重授权登记

**定位**:不做代登录(NexusVault 式服务端重授权不符合本地架构);只做「重授权产物登记」——你用本地 OA 授权工具链跑完后,把产物导入面板,面板解析并回写。

- [ ] `POST /v0/management/data-records/register-reauth`:上传重授权产物 JSONL
  - 按邮箱匹配库存记录(复用 dedupe 合并语义:产物字段更新,不覆盖库存中更新的活字段)
  - 解析并回写:`reset_expired_at`(重置后过期日期)、`reauth_at`(本次重授权日期)、新 access_token/refresh_token
  - `auth_state` 翻回 `authorized`;`health` 重置为 `unknown`(等下次检测)
- [ ] 前端:库存页「登记重授权」按钮 + 文件上传 + 结果报告(成功/未匹配/字段缺失条数)
- [ ] ⏸ 卡点:需要一份 OA 重授权产物的 JSONL 样本确认字段名(`expired`?`last_refresh`?)——可用 `07.OA授权重跑-200次` 里的产物
- [ ] 未匹配邮箱的产物行:可选「作为新记录入库」(默认开)

## 六、风险与纪律(长期有效)

1. **非空库导入永远带 dedupe**(面板按钮已默认;命令行务必带 `?dedupe=1`),导错可重复执行幂等修复;
2. 每次大批量导入/部署后跑一次 `backup-data.ps1`;
3. 8317 只跑流量,不做任何数据管理操作;
4. 改 Go 补丁面(4+1 文件)后必须重新编译并重启 8318,同时同步 `modified-files/` 归档;
5. `data/`、`custom-addon/`、`backup/` 靠 `.git/info/exclude` 隐身,换机需手动拷贝。
